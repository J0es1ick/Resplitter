# Resplitter

Telegram-бот + React Mini App для совместного разделения ресторанного чека. Интерфейс живёт **в этом репозитории** (`web/`), API и бот — в `src/`. Внешний старый `WEB_APP_URL` больше не используется.

## Возможности

- Фото → Yandex OCR → проверка и исправление **в чате бота** → подтверждение владельцем → Mini App для разделения.
- В боте: страницы чека, изменение/добавление/удаление позиций, итог и валюта. Mini App не получает черновики и не может подтвердить их через API. После исправления подтверждённого чека выбор участников сбрасывается, требуется повторное подтверждение.
- Парсер учитывает колонки и перспективу снимка, переносы названий, бесплатные позиции, количество `3×0.5л` и `15.000`, штрихкоды, отдельные юридические итоги, скидки и обслуживание. RUB/UZS/KZT/USD/EUR/GEL; валюта без явного обозначения предполагается RUB и может быть исправлена в боте.
- Приглашения друзьям, выбор со своего телефона, общие блюда, деление поровну, итог в исходном чате.
- Точное количество у каждого участника: 3 напитка можно распределить как 2 + 1. Поддерживаются дробные порции до 0,001. «Делим вместе» делит остаток после точных количеств поровну между выбравшими этот вариант; одна общая пицца может делиться на троих без потери копеек. Прежние сохранённые отметки сохраняют смысл общего выбора.
- Сервер запрещает превышать количество в чеке, а нераспределённые части блокируют завершение. Одновременные сохранения защищены версией; чужой выбор не перезаписывается, при конфликте свой ввод остаётся на экране.
- Целые копейки, детерминированное распределение остатков. Скидка/сервис (разница итога и суммы позиций) распределяется пропорционально. Нераспределённые позиции блокируют завершение.
- Серверная проверка подписи Telegram `initData`, срока авторизации, доступа к чеку и версии. Чужой Telegram ID из браузера не принимается.
- SQLite WAL, транзакционная финализация, постоянные входящая очередь и очередь уведомлений, TTL и восстановление после перезапуска.
- Polling или защищённый webhook, health/readiness, закрытые метрики, Docker и CI.

## Быстрый тест на Windows

Node.js 22 (не ниже 22.13), npm и установленный Cloudflare `cloudflared`.

1. Укажите реальные `TELEGRAM_TOKEN`, `API_KEY`, `API_FOLDER_KEY` в локальном `.env`. Секреты не коммитятся.
2. Выполните:

```powershell
npm ci
npm run check
npm run build
npm run test:start
```

Если Cloudflare недоступен/обрывается, при уже настроенном ngrok v3 используйте `npm run test:start:ngrok`. Инспекция HTTP-запросов отключена; служебный интерфейс слушает только `127.0.0.1:43131`. Глобальная конфигурация и токен ngrok не изменяются. На этом ПК тестовый запуск проверен именно через ngrok.

В первом окне ngrok может потребоваться самостоятельно подтвердить переход кнопкой **Visit Site**. Это ограничение тестового tunnel; для production нужен собственный постоянный HTTPS ingress.

Скрипт создаёт временный HTTPS tunnel, записывает **только настройки запуска** в игнорируемый `.env.runtime`, запускает бота скрыто и ждёт readiness. Бот сам обновляет системную кнопку Telegram «Mini App». В чате с ботом: `/demo` → проверить/исправить чек в сообщениях → «Всё верно → разделить» → открыть Mini App → пригласить друга → выбрать блюда → завершить. Для настоящего чека отправьте фото. `/app` или «Мои чеки» в главном меню открывает каталог: «Открытые» (черновики и незавершённое разделение) и «Закрытые» (завершённые расчёты, только просмотр). Каждый раздел показывает до 6 кнопок чеков на странице с номером, датой и суммой. Сам чек открывается только по выбору; «К списку чеков» возвращает на прежнюю страницу. Истёкшие чеки не показываются — каталог не является бессрочным архивом. В группах видны только чеки этого чата, которые создал пользователь или к которым присоединился; полный личный каталог доступен в личке. Бот должен иметь права для проверки участия (рекомендуется администратор); Mini App открывается через личный чат.

Для правки позиции напишите `Чай, 580, 2`, `Чай. 580. 2` или `Чай 580 2`: название, сумма за всю позицию (не за одну чашку), количество. Для дробных значений: `Чай, 580,50, 1,5`; после разделителей ставьте пробелы. Суммы с тысячами: `Чай, 1 580,50, 2`. Старый формат с `|`, точка с запятой и три отдельные строки также поддерживаются. В личном чате достаточно обычного сообщения; в группе нужно ответить **на сообщение-запрос бота**. При ошибке бот повторяет запрос и продолжает ждать исправление, не выходя из редактирования. Итог не пересчитывается автоматически, чтобы не скрыть ошибки распознавания. `/cancel` отменяет ввод. В Mini App вкладка «Чек» доступна только для чтения; владелец может вернуться к редактированию в боте.

«В главное меню», `/start`, `/back` и `/cancel` показывают только главное меню, без автоматического открытия последнего чека. Сохранённые черновики и подтверждённые чеки доступны по отдельной кнопке «Мои чеки» или через `/app`.

Навигация, каталог, карточка чека и меню исправлений используют одно редактируемое сообщение на пользователя в чате. Его ID и последняя страница каталога сохраняются в SQLite и переживают перезапуск. Если сообщение удалено или недоступно для редактирования, бот убирает его клавиатуру, когда Telegram позволяет, и создаёт замену. Старые меню из предыдущих версий не удаляются массово: при нажатии они переводятся в новую навигацию; старые личные клавиатуры отключаются по мере использования. В группе экран одного участника не заменяется экраном другого. Запросы текстового ввода ForceReply приходят отдельными сообщениями без новых inline-клавиатур; итог расчёта также остаётся отдельной записью в истории.

После открытия или подтверждения чека бот запоминает текущий чек. В инструкции, помощи для компании, сведениях о хранении, главном меню и каталоге появляется «К текущему чеку»: она возвращает к карточке с Mini App (или к странице проверки черновика), а не требует заново искать чек. Контекст сохраняется после перезапуска; права, срок хранения и статус проверяются повторно.

Повторная загрузка фотографии тем же пользователем в тот же чат открывает существующий чек, не сбрасывая правки, подтверждение и выбор участников. Идентичное изображение узнаётся по Telegram `file_unique_id`, без повторного OCR. Для новой копии снимка дополнительно сверяются номер, дата, время, валюта, итог и состав позиций; одного совпадения номера/суммы недостаточно. При неполных данных или неоднозначности автоматическое объединение не выполняется. Разные пользователи и разные чаты остаются независимыми.

Для заранее проверенных исторических дублей есть административный скрипт `node scripts/link-duplicate-drafts.cjs database.sqlite duplicateId canonicalId [...]` (после backup и сборки). Он связывает старый черновик с подтверждённым чеком в транзакции, сохраняя обе исходные записи; каталог скрывает дубль, прежние ссылки ведут к актуальному чеку, устаревшие кнопки редактирования отклоняются. Скрипт не объединяет выбор участников и отказывает для черновика с чужими участниками, выбранными позициями, приглашением, другой областью доступа или несовпадающим чеком.

После новой сборки `npm run test:restart:bot` перезапускает только уже работающий тестовый бот этого проекта, проверяя PID, время старта и путь. Туннель, публичный адрес и база остаются прежними. Скрипт проверяет локальный readiness; доступность внешнего HTTPS проверяется отдельно.

## Как пользоваться компанией

1. Автор отправляет фото в личный чат бота и проверяет **все страницы**. На каждой странице указаны её номер, диапазон позиций и общий итог за весь чек.
2. После подтверждения открывает Mini App → **«Пригласить друзей»** и отправляет ссылку в общий чат.
3. Каждый участник открывает одну и ту же ссылку **со своего Telegram-аккаунта**, запускает бота, открывает Mini App и сохраняет свои позиции/количества. Загружать фото повторно не нужно.
4. Для отдельных напитков укажите «Моё количество»; для общей еды — «Делим вместе». «Кто сколько» показывает сохранённые доли и выбранные количества. Обновление других участников происходит примерно каждые 8 секунд, не затирая текущий ввод.
5. Когда все готовы, автор завершает расчёт. До распределения всех платных частей завершение запрещено. Итог отправляется в исходный чат.

Можно загрузить фото сразу в группу с ботом: участники переходят по кнопке «Разделить чек» в личный чат с ботом, затем в приложение; итог возвращается в группу. Для надёжной проверки состава группы боту нужен статус администратора — см. [Telegram getChatMember](https://core.telegram.org/bots/api#getchatmember). Права удаления сообщений не требуются. Если действует privacy mode, отправляйте фото ответом на сообщение бота; [правила доставки сообщений Telegram](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get). Присоединившиеся участники видят чек в «Моих чеках», пока состоят в группе.

Эта инструкция доступна в `/group`, по кнопке «Как разделить компанией?» и в блоке «Вместе проще» приложения. На экранах бота есть возврат в меню; `/back` и `/cancel` отменяют только текущий ввод данного пользователя, не удаляя чек или выбор остальных.

```powershell
npm run test:stop
```

Остановка затрагивает только PID этого тестового запуска, с проверкой времени старта и командной строки. На Windows это завершение процессов; незавершённая очередь восстанавливается из SQLite. Логи и база остаются в `data/`.

## Порты и обычный запуск

| Назначение                                 | Адрес             |
| ------------------------------------------ | ----------------- |
| Бот/API/собранный Mini App                 | `127.0.0.1:43127` |
| Vite для разработки React                  | `127.0.0.1:43128` |
| Метрики тестового tunnel (только loopback) | `127.0.0.1:43130` |

`npm start` запускает собранный проект. Нужен `MINI_APP_URL=https://ваш-домен` **без `/app`**. Интерфейс доступен по `/app/`. Для UI-разработки: `npm run dev:web`; браузерный `/app/?demo=1` работает на локальном примере, **не авторизует API** и не сохраняет реальные чеки.

`.env.runtime` приоритетнее `.env`; переменные окружения процесса приоритетнее обоих. Перед production удалите/перенесите тестовый `.env.runtime`. Docker не копирует ни один локальный env-файл.

За reverse proxy перечислите в `TRUSTED_PROXY_IPS` через запятую только точные IP-адреса доверенных прокси на пути к приложению. Прокси должен перезаписывать `X-Forwarded-For` адресом подключившегося клиента или дописывать этот адрес справа; приложение проходит цепочку справа налево до первого недоверенного узла. `Forwarded` и другие заголовки с адресами игнорируются. При пустом списке учитывается только адрес подключения. Нельзя включать в доверенный список адреса клиентов или прокси, не проверяющие свой входящий трафик: это разрушает границу доверия.

Для итоговых уведомлений outbox ограничивает частоту отправки по чатам и для всей очереди. Telegram не указывает надёжно область действия ответа 429, поэтому очередь консервативно выдерживает `retry_after` перед отправкой в любой чат, сохраняя срок ожидания после перезапуска. Остальные вызовы Telegram вне outbox имеют отдельное поведение библиотеки и не управляются этим ограничителем.

## Проверки

```sh
npm run check
npm run format:check
npm run build
npm audit
```

Тесты покрывают подпись и expiry Telegram, доступ/версии HTTP API, native-сценарий редактирования и подтверждения, устаревшие кнопки и ответы, совместные позиции, копейки, повторное завершение, rollback/CAS, сохранение и восстановление очереди. В `tests/fixtures/ocr/` — обезличенные ответы OCR для шести предоставленных фото, без самих изображений, имён сотрудников и реквизитов организаций. Тесты не вызывают настоящий Telegram/OCR. Браузерные проверки выполняются отдельно.

`OCR_ENHANCED_RETRY=true` разрешает **один дополнительный запрос** к тому же Yandex OCR для сложного чека: обрезка по тексту, увеличение и контраст выполняются локально в памяти. Это увеличивает стоимость и задержку OCR. Повторный проход дополняет количество только при совпадении названия и всей последовательности сумм. Если OCR не видит цифру, бот показывает предупреждение, а не восстанавливает её из желаемого итога. Подробнее: [результаты проверки парсера](docs/OCR-VALIDATION.md).

## Границы production

Это архитектура **одной реплики на постоянном локальном диске**; сетевой файловый ресурс для SQLite и параллельные экземпляры не поддерживаются. Обработчик входящих сообщений последовательный; долгий OCR задерживает новые команды, но API Mini App работает независимо. Для высокой нагрузки нужны очередь OCR с отдельными workers и общий transactional store.

Временный tunnel — только тестовый стенд, не production-хостинг. Для релиза нужны постоянный HTTPS-домен, supervisor, резервные копии, алерты, проверка реальными чеками и двумя аккаунтами Telegram. OCR не гарантирует безошибочного распознавания: обязательная проверка человеком является частью сценария.

См. [эксплуатацию](docs/RUNBOOK.md), [данные и хранение](docs/PRIVACY.md), [проверку перед релизом](docs/ACCEPTANCE.md).
